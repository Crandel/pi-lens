- **`package.json` now declares `engines.node` (refs #2633)** — it declared no `engines` field, so a fresh install of pi-lens on a Node below `typescript-language-server@6.0.0`'s own `>=22.22.2` floor printed a confusing `npm WARN EBADENGINE` about a transitive devDependency instead of pi-lens stating its own promise. The pi host itself (`@earendil-works/pi-coding-agent@0.84.x`–`0.85.1`) floors at `node >=22.19.0`, lower than `typescript-language-server@6.0.0`'s `>=22.22.2` — since pi-lens must never demand more than the pi host does, `typescript-language-server` is pinned back to `5.3.0` (`engines.node >=20`) and `engines.node` is declared at pi's own floor, `>=22.19.0`, which already exceeds every production dependency's own floor (checked against `>= 10`–`>=18` across `@ast-grep/*`, `pidusage`, `vscode-jsonrpc`, `minimatch`'s disjunctive range, and friends). `tests/config/engines-node-floor.test.ts` is new governance: it walks `package-lock.json`'s production (non-`dev`) entries and asserts `engines.node` is a `semver.subset` of every one of their own `engines.node` ranges, and separately rejects a wildcard/unbounded range (`"*"`) as a cheap way to pass that check vacuously. `README.md`'s install section now states the floor.
  - The install-smoke / release-qa EBADENGINE row belongs to #2613/#2606, not this issue — refs only, not closed here.
