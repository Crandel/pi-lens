- **Managed CSS Language Server install no longer targets a dead npm package (closes #2638)** — `clients/installer/index.ts`'s `TOOLS` registry pointed the `vscode-css-languageserver` id at a bare npm package of the same name, which was unpublished from the registry on 2021-07-22 (`npm view vscode-css-languageserver` returns `E404`); `ensureTool("vscode-css-languageserver")` could never succeed. The CSS server ships today inside `vscode-langservers-extracted` — the same unpinned package the sibling `vscode-json-language-server` entry already installs, which bundles the `vscode-css-language-server`/`vscode-html-language-server`/`vscode-json-language-server`/`vscode-eslint-language-server`/`vscode-markdown-language-server` bins together — so the entry's `packageName` is repointed there. `npm view vscode-langservers-extracted engines` reports no floor, so (unlike `typescript-language-server`, #2633) there is no EBADENGINE reason to pin it; it stays unpinned like its JSON sibling. A new network-gated integration test (`tests/clients/installer/registry-resolve.integration.test.ts`, `PI_LENS_INTEGRATION=1`, matching the existing live-network suite gate) asserts every `installStrategy: "npm"` TOOLS entry's bare package name resolves a real `dist-tags.latest` on the npm registry, red-first against the pre-fix entry; `tests/clients/installer/managed-tool-ids.test.ts` gains a network-free assertion pinning the corrected `packageName`/`binaryName`.
